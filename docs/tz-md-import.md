# ТЗ-16: Импорт Markdown в редактор контента (админка)

Статус: черновик на согласовании 2026-11-25.
Контекст: отчёты для публикации поставляются в MD с картинками в base64
(пример: `Applied_Intuition_разбор_самодостаточный.md`, 342 КБ, 3 изображения
по ~75 КБ, 14 заголовков, таблицы). Сейчас перенос ручной: копипаст текста +
каждую картинку отдельно через медиатеку. Импортёр должен превращать такой файл
в черновик статьи за одну операцию, нормализуя картинки в медиатеку
(base64 — формат передачи, не хранения: не кладём data-URI в `content_html`).
Термин «редактор» — TipTap (`apps/admin/src/components/RichTextEditor.tsx`),
обёртки: `ArticleEditPage`, `ContentMasterPage`.

## Задача 1. Вход и UI импорта

**Проблема:** нет точки входа — MD можно только руками переносить.

**Решение:**
1. Кнопка **«Импорт MD»** в панели редактора (обе обёртки, один компонент).
2. Модал: drop-zone файла (`.md`/`.markdown`/`.txt`) + поле вставки текста.
   Лимит текста — 2 МБ, при превышении понятная ошибка.
3. После выбора — **превью-статистика**: «Заголовок: …; разделов: N; картинок: K
   (base64 — будут загружены в медиатеку; внешние — останутся ссылками);
   таблиц: M». Кнопка «Импортировать» активна после превью.
4. Импорт вставляет HTML в текущий документ редактора (заменяя содержимое —
   подтверждение, если документ не пустой).

**Проверка:** файл из контекста → превью показывает 14 разделов/3 картинки;
импорт → содержимое редактора = конвертированный отчёт; в непустой документ
без подтверждения импорт не начинается.

## Задача 2. Конвертация MD → HTML

**Проблема:** редактор работает с HTML, MD нужно конвертировать.

**Решение:**
1. `markdown-it` (уже есть в deps экосистемы web; если нет — добавить в admin)
   с включёнными: заголовки, списки, **таблицы**, жирный/курсив/код,
   блок-код, цитаты, ссылки, изображения. HTML внутри MD — экранируется.
2. Маппинг заголовков: H1 → извлекается в заголовок статьи (см. задачу 4),
   **не вставляется в тело**; H2 → `<h2>`; H3+ → `<h3>` (добавить стили
   `[&_h3]` в prose-селекторы `ArticlePage` и `LoadedArticle` — сейчас
   стилизован только h2).
3. Результат вставляется через существующий пайплайн редактора
   (`editor.commands.setContent`) — серверная санитизация при сохранении
   остаётся единственной внешней защитой, как и для ручного ввода.

**Проверка:** отчёт из контекста импортируется со всеми таблицами и списками;
`<script>` внутри MD в теле статьи после сохранения отсутствует (экранирован
конвертером и/или санитизатором — проверить оба слоя на тестовом вводе).

## Задача 3. Картинки: base64 → медиатека

**Проблема:** data-URI в `content_html` раздувают БД, не кэшируются,
не переиспользуются, минуют sharp-обработку.

**Решение:**
1. Перед вставкой в редактор DOM-разбор HTML: каждый `<img>` со `src`
   `data:image/*;base64` декодируется → `Blob` → существующий
   `POST /api/media/upload` (тот же, что у кнопки загрузки; sharp сам
   пережмёт в webp). После успеха `src` заменяется на вернувшийся
   `/uploads/…`, `alt` сохраняется.
2. Загрузки идут последовательно; падение одной → остальные продолжают,
   упавшая остаётся data-URI с предупреждением в превью результата.
3. Лимит одной картинки — 10 МБ после декодирования (guard до upload).
4. `<img>` с внешним `http(s)://` — v1 оставляем как есть, в превью
   помечаем «внешние: K — останутся ссылками» (загрузка по URL — отдельная
   задача, не входит).

**Проверка:** импорт файла из контекста → 3 новые записи в медиатеке
(webp), в HTML статьи `src="/uploads/…"`, data-URI отсутствуют; alt
сохранён; удаление статьи не удаляет media-файлы (связь как при ручной
загрузке — поведение не меняется).

## Задача 4. Заголовок и тезис

**Проблема:** H1 в MD — это заголовок статьи, а не элемент тела.

**Решение:** первый H1 извлекается и предзаполняет поле «Заголовок»
(если поле пустое — без подтверждения; если занято — в превью чекбокс
«заменить заголовок»). Первый абзац после H1 (до 300 символов) предлагается
в поле «Тезис» аналогично.

**Проверка:** импорт отчёта → заголовок «Applied Intuition: разбор
инвестительного предложения ФИНАМ на $40 млрд»; тезис — первый абзац;
при заполненных полях ничего не затирается без чекбокса.

## Задача 5. Границы и деградация

1. **Front matter** (`---` блок в начале) — v1 не поддерживаем: показать
   предупреждение в превью, импортировать как обычный текст.
2. **Нет H1** — импорт тела как есть, заголовок не трогаем.
3. **Пустой файл / не-MD текст** — превью «разделов: 0, картинок: 0»,
   импорт допустим (вставится абзац).
4. **Ошибка сети при загрузке картинки** — см. задача 3.2.
5. **Дубликат импорта** — импортёр идемпотентен за счёт медиатеки:
   повторный импорт создаёт новые media-записи (как ручная загрузка),
   статья не дублируется без явного сохранения.

**Проверка:** каждый пункт — отдельный тестовый файл; отсутствие падений
редактора во всех пяти.

## Что НЕ входит в ТЗ

- Загрузка внешних картинок по URL в медиатеку.
- Импорт из DOCX/HTML/Google Docs.
- Пакетный импорт (несколько файлов → несколько статей).
- Front matter.
- Авто-привязки сущностей (компании/тренды из текста) — есть ИИ-кнопки
  в ContentMaster, ортогонально.

## Реализация (планируемое касание файлов)

- `apps/admin/src/components/MdImportModal.tsx` — новый (UI, drop/paste,
  превью, оркестрация).
- `apps/admin/src/lib/mdImport.ts` — новый (markdown-it конфиг, извлечение
  H1/тезиса, выгрузка картинок, замена src).
- `apps/admin/src/components/RichTextEditor.tsx` — кнопка «Импорт MD»
  (пропс/слот; обе обёртки получают автоматически).
- `apps/web/src/pages/ArticlePage.tsx`, `apps/web/src/components/AutoLoadNext.tsx`
  — добавить `[&_h3]` в prose-селекторы.
- API — без изменений (используется существующий `/api/media/upload`).

## Приёмка

1. Импорт файла из контекста в ContentMaster → черновик готов к публикации
   без ручных правок текста; картинки из медиатеки; обложка — по кнопке
   из медиатеки (как раньше).
2. Импорт в ArticleEdit в существующую статью — подтверждение замены,
   поля заголовка/тезиса по правилам задачи 4.
3. XSS-ввод из задачи 2 не доходит до `content_html`.
4. Запись в журнале `newinvesticionno.md` после деплоя.
