# Интеграция base64-картинок в TipTap (импорт Markdown, ТЗ-16)

Документ фиксирует итоговое решение и все ошибки, которые пришлось пройти, чтобы
его можно было воспроизвести 1:1 на другом проекте (например, PULSE).
Статус: актуально на 2026-11-26, код задеплоен.

## 1. Задача

Поставщики контента присылают отчёты в Markdown с картинками в base64
(`![alt](data:image/png;base64,…)`), сносками `[^id]`, таблицами, H1–H4.
Пример файла: 342 КБ, 3 картинки по ~75 КБ, 39 сносок, 4 таблицы, 14 заголовков.
Требование: один импорт → черновик статьи в админке, картинки — в медиатеке,
base64 в `content_html` не попадает (base64 — формат передачи, не хранения).

## 2. Архитектура (итоговое решение)

```
MD-файл
  │  MdImportModal (drop / paste / выбор файла)        apps/admin/src/components/MdImportModal.tsx
  ▼
previewMd()  — статистика без рендера: H1, разделы, картинки (base64/внешние),
  │            таблицы, сноски, front matter, лимит 2 МБ (по UTF-8 байтам)
  ▼  (подтверждение пользователя; непустой документ — confirm)
importMarkdown()                                     apps/admin/src/lib/mdImport.ts
  ├─ extractTitleAndThesis()   — первый H1 (строго в начале файла) → заголовок;
  │                              первый абзац после H1 (≤300 симв.) → тезис;
  │                              строка H1 удаляется из тела
  ├─ extractFootnoteDefs()     — строки `[^id]: текст` вырезаются из тела → Map
  ├─ md.render()               — markdown-it { html:false, linkify:true }
  ├─ DOMParser → <img> с data: → последовательно uploadImage():
  │    декодирование atob → Blob → POST /api/media/upload (multipart)
  │    → ответ { filePath: '/uploads/<id>-<hash>.webp' } → замена src
  ├─ root.innerHTML
  └─ renderFootnotes()         — `[^id]` → текстовый `[N]` (НЕ sup/a/id!)
                                 + в конец: <h2>Источники и примечания</h2><ol>…</ol>
                                 (определения через md.renderInline — linkify URL)
  ▼
editor.commands.setContent(html, { emitUpdate: true })   RichTextEditor.tsx
  ▼
onChange → setDirty(true) → автосохранение (ТЗ-11)
onImportedMeta({title, thesis}) → поля формы (по чекбоксам)
```

Задействованные файлы (монорепо, воркспейс `apps/admin`):

| Файл | Роль |
|---|---|
| `src/lib/mdImport.ts` | всё ядро: previewMd, importMarkdown, extract*, renderFootnotes, SessionExpiredError, uploadImage |
| `src/components/MdImportModal.tsx` | UI: drop-zone, textarea, превью, чекбоксы, импорт, экран результата |
| `src/components/RichTextEditor.tsx` | кнопка «⬇ MD» в Toolbar; пропсы `onImportedMeta`, `importFields`; передача в модал |
| `src/pages/ArticleEditPage.tsx` | `importFields={{title, thesis}}` из form; подстановка в form + slug; setDirty |
| `src/pages/ContentMasterPage.tsx` | то же для своих title/thesis state |
| сайт: `apps/web/src/pages/ArticlePage.tsx`, `apps/web/src/components/AutoLoadNext.tsx` | prose-стили `[&_h3]` (был только h2) |

TipTap-конфиг редактора (без изменений фичи): StarterKit `heading levels [2,3,4]`,
`Image`, `Table*`. **Расширения Superscript/Link для сносок НЕ добавлялись** (см. §4, ошибка 4).

## 3. Внешние контракты

- `POST /api/media/upload` — multipart `file`, Bearer-токен; сервер: multer в память →
  валидация mimetype + magic bytes → `optimizeImage` (sharp → **webp**, пережатие) →
  уникальное имя `/uploads/<ms>-<hash>.webp` → запись в таблицу `media`. Ответ: `{ url, filePath, media }`.
- Санитизация HTML: на рендере сайта (`web/lib/sanitize.ts` allowlist) — серверной
  санитизации при сохранении НЕТ (zod-строка), модель доверия: админка за токеном + `html:false`.
- Автосохранение ArticleEditPage завязано на флаг `dirty` (`beforeunload` + autosave-эффект).

## 4. Ошибки и решения (хронология — все реально случились)

### Ошибка 1. Мусор `[^forbesprofile]` после импорта
**Причина:** markdown-it без плагина не парсит CommonMark footnotes — ссылки и
определения проходят как литеральный текст.
**Решение (итог):** свой препроцессор: `extractFootnoteDefs()` вырезает
`[^id]: текст` из тела ДО рендера, `renderFootnotes()` ПОСЛЕ рендера заменяет
инлайн-ссылки и дописывает концевой список. Однострочные определения только
(поставщики так шлют); многострочные — не поддерживаются (зафиксировано).

### Ошибка 2. Красный `tsc --noEmit` — сборка типов падала
**Причина:** в интерфейс `MdImportPreview` добавили поле `footnoteDefs`, а литерал
объекта ошибки в `MdImportModal` (ветка «файл > 2 МБ») не обновили. Vite-build
проходил (tsc в него не входит), флаг поймал ревью.
**Решение:** добавить поле в литерал; урок — после правки интерфейсов гонять
`npx tsc --noEmit`, не полагаться на `vite build`.

### Ошибка 3. Кнопки затирали заполненные поля против ТЗ
**Причина:** один общий чекбокс «подставить заголовок и тезис», дефолт ON; форма
заменяла непустые поля без предупреждения.
**Решение:** пропс `importFields: { title, thesis }` в RichTextEditor (передают
родительские формы) → два отдельных чекбокса, дефолт = подставлять только в
пустые поля; у занятого — янтарная пометка «будет заменено». Slug пересобирается
только если пуст или равен `slugify(старого title)` — ручной slug не трогаем.

### Ошибка 4. Сноски до сайта не доезжают (самое важное замечание ревью)
**Причина:** изначально рендерили `<sup><a href="#fn-N">[N]</a></sup>` +
`<li id="fn-N">`. Пайплайн их убивает в два слоя:
- TipTap StarterKit без расширений: тег `sup` роняется, mark `link` теряется
  (нет расширения Link), атрибут `id` на `li` не сохраняется;
- sanitize на сайте: `sup` не в allowlist, `id` запрещён на всех тегах.
На выходе — «[1]» без работающего якоря: мёртвые ссылки.
**Решение (вариант «б» ревьювера — выбран):** честный текстовый номер `[N]`
без тегов и без `id`; концевой `<ol>` просто списком. Навигации нет, но ничего
не обещаем и ничего не теряется. Проверка на файле: 39 сносок, 84 ссылки `[N]`,
0 остатков `[^..]`, 0 лишних тегов.
**Альтернатива (не делали):** TipTap-расширения Superscript + Link + расширение
обоих sanitize-allowlist (`sup`, `id`) — дороже, навигация по якорям в редакторе
всё равно полумёртвая.

### Ошибка 5. Автосохранение пропускало и импорт, и обычную печать
**Причина:** `onChange` редактора в ArticleEditPage делал `setForm` без
`setDirty(true)`; autosave и `beforeunload`-предупреждение завязаны на `dirty`.
Сценарий потери: «импортнул → закрыл вкладку → черновика нет».
**Решение:** `setDirty(true)` в `onChange` редактора и в `onImportedMeta`.

### Ошибка 6. «3 не загрузились» + медиатека 401 — протухшая сессия
**Причина:** токен админа живёт 12 часов (аудит 2026-11-08). Конвертация текста
API не нужна — разделы/сноски встали; картинки и медиатека (нужен API) — 401.
Первоначальный обработчик делал редирект на `/login`, но он мог молча
отменяться браузером (`beforeunload`-предупреждение грязной формы) — пользователь
остаётся на странице с непонятным «не загрузились».
**Решение:** `SessionExpiredError` — пробрасывается наверх, модал показывает
понятное сообщение «перелогиньтесь и повторите», импорт **прерывается целиком**
(контент не вставляется наполовину). Токен из localStorage удаляется.
**Заодно выяснено:** импортер дубликатов не ищет — повторный импорт того же файла
создаст второй комплект картинок в медиатеке (записано в todo).

### Ошибка 7. h3+ не стилизованы на сайте
**Причина:** prose-селекторы статей стилизовали только `[&_h2]`; MD с H3–H4
(отчёт имел 5 штук) рендерился без стилей.
**Решение:** добавлено `[&_h3]:mt-6 [&_h3]:text-lg [&_h3]:font-semibold` в
ArticlePage и AutoLoadNext (LoadedArticle).

### Ошибка 8 (принято, не исправлено). h5/h6 схлопываются
TipTap настроен на `levels [2,3,4]` — h5/h6 из MD теряют заголовочность
(текст остаётся). Маппинг h5/h6 → h4 не делали; в todo.

## 5. UX-детали модала (чтобы перенос был 1:1)

- Drop-zone с `onDrop` + скрытый `<input type="file" accept=".md,.markdown,.txt">`;
  после выбора file input сбрасывается (`value=''`) — иначе повторный выбор того
  же файла не сработает.
- Лимит 2 МБ проверяется ДВАЖДЫ: по размеру файла и по UTF-8 байтам текста
  (`new TextEncoder().encode(s).length`) — русские символы = 2 байта.
- Превью считается по сырому тексту (быстро), картинки — regex'ом
  `!\[…\]\(…\)`; счётчики учитывают код-блоки (завышение допустимо, в todo).
- Overlay закрывается кликом, но НЕ в состоянии `busy` (нельзя случайно убить
  загрузку картинок).
- Непустой документ → `window.confirm` перед заменой.
- Экран результата: «разделов N, таблиц M, сносок K → Источники», по картинкам —
  «X → медиатека, Y не загрузились (остались base64)».
- Кнопка в тулбаре: `⬇ MD`, title-подсказка «Импорт Markdown (ТЗ-16)».

## 6. Лимиты и деградации (контракт фичи)

| Ситуация | Поведение |
|---|---|
| > 2 МБ текст | ошибка в превью, импорт заблокирован |
| картинка > 10 МБ после декодирования | пропуск (guard до upload) |
| внешние http(s) картинки | остаются ссылками, пометка в превью |
| падение загрузки одной картинки | остальные продолжают; упавшая остаётся base64 с предупреждением |
| 401 на upload | SessionExpiredError, импорт прерван, понятное сообщение |
| ссылка `[^id]` без определения | остаётся как есть |
| front matter `---` | не поддерживается: предупреждение в превью, импортируется как текст |
| без H1 / H1 не в начале файла | заголовок не предлагается |
| не-UTF8 файл | readAsText молча даёт U+FFFD (детект в todo) |

## 7. Проверки для переноса 1:1

1. `npx tsc --noEmit` — 0 ошибок (не только `vite build`).
2. Прогон эталонного файла (342 КБ, 3 base64, 39 сносок, 4 таблицы):
   defs=39, used=39, остатков `[^..]`=0, sup-тегов=0, `<script>`=0.
3. Импорт в пустой документ → заголовок/тезис подставлены; в заполненный →
   только по чекбоксам, ручной slug не изменился.
4. Публикация → на сайте: h2/h3 стилизованы, таблицы с границами, картинки
   `/uploads/*.webp`, в `content_html` нет `data:image`.
5. Истечение токена (или мусорный Bearer): модал показывает сообщение о сессии,
   контент не вставлен.
6. Автосохранение срабатывает после импорта (dirty) и после печати.
