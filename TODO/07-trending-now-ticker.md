# ТЗ-07. Trending Now — тиккер «Сейчас читают» в шапке

**Вводная владельца:** «настоящий трендинг NOW тиккер. реалтайм можно. с накоплением за 6 часов. если обновления не было — рефреш раз в 15 минут».

**Статус:** ТЗ (к реализации) · **Приоритет:** после пейволла и метрик (использует `article_views`, публичный доступ к статьям)

---

## 1. Цель

Горизонтальная бегущая лента в шапке сайта «Сейчас читают: …», показывающая топ-N статей по реальным просмотрам за последние 6 часов. Заголовки кликабельны, ведут на статью. Даёт эффект «живого» медиа и повышает глубину просмотра, не требуя ручной модерации — рейтинг считается автоматически из `article_views`.

## 2. Текущее состояние (что уже есть в коде)

- **Данные:** таблица `article_views` (`packages/db/src/schema.ts`, строка 430) — `article_id`, `viewed_at` (timestamptz, дефолт `now()`), опциональный `user_id`; есть индекс `(article_id, viewed_at)`. Просмотр пишется при открытии статьи (`apps/api/src/routes/articles.ts`, строка 158, fire-and-forget `.catch(() => {})`).
- **Шапка:** `apps/web/src/components/Layout.tsx` — единый `<header>` на всех страницах, тёмная тема, акцент `#beff00`. Тиккер встраивается сюда.
- **Статьи:** таблица `articles` имеет `status` (`draft | pending | published`), `accessLevel` (`public | auth | tariff`), уникальный индекс `(type, slug)`. URL статьи: `/{type}/{slug}` (по аналогии с `TrendPage`, `CompanyPage`).
- **Фронтенд:** React Query уже подключён (`apps/api`… точнее `apps/web/src/main.tsx`, `QueryClientProvider`), запросы идут через хелпер `api` (`apps/web/src/pages/HomePage.tsx`). Отдельного поля `viewsCount` в схеме нет — ТЗ-03 (виртуальный счётчик) ещё не реализован.
- **API:** роутеры в `apps/api/src/routes/*.ts`, регистрация в точке входа API (рядом с `articlesRouter`). Публичных эндпоинтов без guard'ов много — прецедент есть, но см. комментарий баг 2026-11-08 в `metrics.ts`: guard'ы ставить на уровне конкретных роутов, не `router.use`.

## 3. Требования

### 3.1. Поведение
1. Тиккер — горизонтальная бегущая строка (marquee) в шапке, сразу под `<header>` (или нижней границей шапки — см. 4.2), формат: **«Сейчас читают:»** + циклично повторяющаяся лента `Заголовок • Заголовок • …`.
2. Клик по заголовку → переход на страницу статьи.
3. Виден **на всех страницах** (встроен в `Layout`), в компактной однострочной высоте (~32–36 px), не перекрывает контент.
4. Пауза анимации при наведении курсора (иначе клик по движущемуся заголовку недостижим).
5. Если за окно накопления (6 ч) нет ни одного просмотра — тиккер **скрыт целиком** (принцип 4.3: показываем только внесённое). Fallback «последние опубликованные» не используем — это подменяет реальный сигнал «сейчас читают» искусственным.
6. Пейволл: в тиккер попадают **только `status='published'` и `accessLevel='public'`** статьи. Обоснование: тиккер виден анонимам, тизерить paywall-контент (клик → модалка оплаты) в «сейчас читают» — плохой опыт и обесценивает доверие к ленте.

### 3.2. Данные
- Рейтинг: `count(*) по article_views` за окно `viewed_at >= now() - interval '6 hours'`, join к `articles` с фильтрами выше.
- N = **10** (параметр, см. 3.3). При коротком списке (1–2 статьи) лента дублирует элементы, чтобы marquee заполнил строку; при 0 — скрыт.
- Формат показа: **заголовок + счётчик 👁 N** (N — просмотры за 6-часовое окно). Это не «всего просмотров» и не будущий `viewsCount` из ТЗ-03; совместимость сохраняется: ТЗ-03 может позже показать тот же числовой формат, но за всё время. В ТЗ-07 используем только реальный счёт за окно — виртуальные инкременты в трендинге недопустимы (ломает честность ранжирования).

### 3.3. API
- `GET /api/trending?hours=6&limit=10` — публичный, без авторизации.
  - `hours`: 1–24, дефолт 6; `limit`: 1–20, дефолт 10. Валидация с клампом, как `days()` в `metrics.ts`.
  - Ответ: `{ items: [{ type, slug, title, views }], windowHours, computedAt }`.
- **Кэш в памяти процесса API: 15 минут.** Ключ кэша — `hours:limit`.
- **Решение по частоте (открытый параметр владельцу):** владелец сказал «реалтайм можно» и «рефреш раз в 15 минут если обновления не было». Компромисс: кэш **5 минут**, TTL сбрасывается досрочно, если с момента последнего вычисления в `article_views` появились новые строки (проверка `max(viewed_at)` — дешёвый запрос по индексу). Это даёт реалтайм при активном трафике и автоматический откат к ≤15-минутному рефрешу в простое. **Дефолт по ТЗ — именно так; если владелец настаивает на жёстких 15 минутах — меняется одна константа `TRENDING_TTL_MIN = 15` и убирается инвалидация по max(viewed_at).**
- Один SQL-запрос, индекс `(article_id, viewed_at)` покрывает окно через join; при росте объёма (>1M просмотров/сутки) — пересмотреть на materialized view (отдельное ТЗ, не блокер).

### 3.4. Фронтенд
- Компонент `TrendingTicker` (`apps/web/src/components/TrendingTicker.tsx`), монтируется в `Layout.tsx` сразу после `</header>` (линия после строки 44).
- Данные: `useQuery({ queryKey: ['trending'], queryFn: () => api.trending(), refetchInterval: 5 * 60 * 1000 })` — фронт тоже не должен долбить API чаще кэша; при открытии новых вкладок каждая обновится по своему таймеру — приемлемо, бэкенд-кэш всё равно держит нагрузку.
- Пустой `items` → компонент возвращает `null` (тиккер не рендерится, разметка не скачет).
- Marquee: CSS animation (`@keyframes translateX`, длительность привязана к ширине ленты, бесшовный цикл через дублирование контента ×2). **Обязательно:** `@media (prefers-reduced-motion: reduce)` — анимация отключена, лента заменяется на статичный горизонтальный скролл.
- Мобильная адаптация: на `<640px` marquee работает, но кегль уменьшается (text-xs), чтобы заголовок влезал; альтернатива — горизонтальный скролл с snap вместо анимации (решение за реализатором, критерий: заголовок читаем и кликабелен на тач-устройстве).
- Стили в духе шапки: тёмная плашка `#111` с бордюром `#2a2a2a`, префикс «Сейчас читают» — акцентный `#beff00`, счётчик 👁 — `text-zinc-500`.

## 4. Реализация (чек-лист)

1. **`apps/api/src/routes/trending.ts`** — новый роутер: парсинг `hours`/`limit`, SQL через `db.execute` (стиль как в `metrics.ts`), фильтры `a.status='published' AND a.access_level='public'`, группировка, `ORDER BY views DESC, published_at DESC` (детерминированный тай-брейк), `LIMIT`.
2. **Кэш** — `Map<string, { data, computedAt }>` в модуле роутера; инвалидация по TTL и по `max(viewed_at)` (запрос `select max(viewed_at) from article_views` при каждом хите — индексированно, дёшево).
3. **Регистрация роутера** в точке входа API рядом с `articlesRouter` (без guard'ов).
4. **`apps/web/src/lib/api.ts`** (или где живёт хелпер `api`) — метод `trending()`.
5. **`apps/web/src/components/TrendingTicker.tsx`** — marquee-компонент с hover-pause, reduced-motion fallback, скрытием при пустом списке.
6. **`Layout.tsx`** — вставить `<TrendingTicker />` после `</header>`.
7. CSS для marquee — в глобальные стили или CSS-модуль; анимация на `transform` (GPU), не на `left`.

## 5. Критерии приёмки

1. Тиккер виден на любой странице сайта, включая главную и страницу статьи.
2. Клик по заголовку в тиккере открывает соответствующую статью.
3. Показаны только `published` + `public` статьи; paywall-контент в тиккере отсутствует.
4. Счётчики 👁 соответствуют реальным просмотрам за 6 часов (проверка SQL-запросом руками).
5. Пустой результат (нет просмотров за окно) → тиккер полностью отсутствует в DOM, нет пустой плашки.
6. При `prefers-reduced-motion` анимации нет, лента доступна через скролл.
7. Повторный запрос `GET /api/trending` чаще, чем раз в TTL (5 мин активно / 15 мин в простое), возвращает кэш без обращения к тяжёлому SQL (видно по логам/таймингам).
8. `refetchInterval` на фронте не вызывает запросы чаще бэкенд-кэша.
9. При наведении курсора анимация останавливается; клик по остановленному заголовку срабатывает.

## 6. Риски

| Риск | Вероятность | Митигация |
|---|---|---|
| Marquee недоступен (vestibular-расстройства, screen readers) | средняя | `prefers-reduced-motion` → статичный скролл; лента — обычный список ссылок в DOM (семантика `<nav><ul><li><Link>`), не canvas |
| Клик по движущемуся заголовку | высокая | hover-pause обязателен; скорость анимации умеренная (≥40 сек на цикл) |
| Мобильный тач: marquee мешает скроллу страницы | средняя | на touch-устройствах отключать autoplay, оставлять ручной горизонтальный скролл |
| Дёрганье макета при первом refetch (появление/исчезновение тиккера) | средняя | зарезервировать высоту? Нет — принцип 4.3: пусто = нет элемента; лучше микро-скачок, чем пустой блок |
| Кэш в памяти = разные данные на разных инстансах API | низкая (сейчас один инстанс) | при горизонтальном масштабировании перейти на общий кэш (Redis) — зафиксировать в TODO |
| Накрутка просмотров одним пользователем влияет на ранжирование | низкая | окно 6 ч и объём трафика невысоки; при злоупотреблениях — агрегировать по `distinct user_id` или IP (отдельное решение) |
| Долгий SQL при большом объёме `article_views` | низкая | индекс `(article_id, viewed_at)` покрывает; мониторить `pg_stat_statements` |
| TTL 5 мин × N вкладок у пользователей | низкая | бэкенд-кэш консолидирует нагрузку; фронт может не refetch'ить вообще (только mount-fetch) — вариант |

## 7. Открытые вопросы владельцу

1. TTL: 5 мин с инвалидацией по активности (предложено) vs жёсткие 15 мин (дословно из вводной)? — решается одной константой.
2. N = 10 устраивает, или 5 для компактности?
3. Счётчик 👁 показывать публично или только заголовки (счётчик может демотивировать «2 просмотра»)?
4. Тиккер на мобильных: тот же marquee или упрощённый скролл?
