# ТЗ-12: убрать токен GitHub из remote, перевести репозиторий на SSH

Статус: TODO. Обнаружено при аудите 2026-11-15.

## Проблема

В `git remote origin` этого репозитория прописан GitHub PAT открытым текстом в URL:

```
https://vladfa2010:github_pat_...@github.com/vladfa2010/Site1_future.git
```

Токен = доступ к репозиториям, выбранным при создании этого PAT (fine-grained),
с правами записи. Он оседает в:
- выводе команд (`git remote -v`, скриншоты, логи терминала);
- `.git/config` (любой доступ к каталогу проекта = доступ к токену);
- истории shell, если адрес вводился вручную.

## Цель

1. Во всех местах, где репозиторий клонируется/пушится, аутентификация — по SSH-ключу.
2. PAT из remote-URL нигде не остаётся.
3. Использованный PAT отозван на GitHub.
4. Работа VDS (`git pull` при деплое) после изменений — не сломана.

## Шаги

1. **Ревизия использования токена** (чтобы не отозвать то, что ещё нужно):
   - этот Mac: `git -C <repo> remote -v` — зафиксировать, что токен здесь;
   - VDS: `git -C <каталог репо> remote -v` — если там тот же HTTPS+токен,
     VDS тоже надо перевести (шаг 4), иначе отзыв токена сломает деплой;
   - другие машины/клоны — по памяти владельца.
2. **SSH-ключ для GitHub на этом Mac:**
   - сгенерировать выделенный ключ: `ssh-keygen -t ed25519 -C "site1-future-mac" -f ~/.ssh/github_site1` (без passphrase или с ней — по политике владельца);
   - добавить в `~/.ssh/config`: `Host github.com → IdentityFile ~/.ssh/github_site1`;
   - публичный ключ добавить в GitHub: Settings → SSH and GPG keys → New SSH key.
3. **Смена remote на этом Mac:**
   - `git remote set-url origin git@github.com:vladfa2010/Site1_future.git`;
   - проверка: `git fetch origin` и тестовый push (например, этот TODO-файл).
4. **VDS** (если шаг 1 показал HTTPS-токен): та же схема — свой ключ на VDS
   (`ssh-keygen` там, публичный ключ в GitHub), `git remote set-url origin git@github.com:...`,
   проверка `git fetch origin` от того пользователя, который делает деплой.
5. **Отзыв токена:** GitHub → Settings → Developer settings → Personal access tokens
   → revoke токену `github_pat_11AD2...` (тому, что был в URL). Только после того,
   как шаги 3–4 подтверждены работающими.
6. **Контрольная проверка после отзыва:** `git fetch` на Mac и на VDS — оба ок.

## Критерии приёмки

- `git remote -v` на Mac и VDS показывает `git@github.com:...` без токенов.
- Отозванный PAT больше не работает (проверить можно `git ls-remote https://<старый URL без токена>` — должен запросить пароль, а не пустить).
- Деплой-процедура на VDS (`git pull`) после изменений — проверена одним прогоном.

## Риски

- **Отозвать токен раньше времени** = сломать push/pull на всех машинах, где он
  использовался. Порядок шагов обязателен: сначала замена, потом отзыв.
- SSH-ключ без passphrase = тот, кто получил файл ключа, получил доступ к репозиторию.
  С passphrase — ввод при каждом обращении (на сервере допустим ssh-agent).
- На VDS ключ появится у пользователя, который делает деплой — если это root,
  доступ к репо у того, кто получит root VDS (приемлемо, т.к. деплой и так под ним).

## Заметка

Пока ТЗ не выполнено, токен остаётся действующим — не публиковать вывод
`git remote -v` и не пересылать `.git/config`.
