# ТЗ: Видео-плейлисты через сюжеты (story с типом video → плейлист)

> Вводная владельца: «плейлисты. у нас сюжеты?» — являются ли сюжеты нашими
> плейлистами или нужны отдельные видео-плейлисты (как tagDiv video playlist)?

## Цель

Дать медиа «инвестиционно.рф» возможность вести рубрики-«выпуски» видео
(YouTube/RuTube/VK) в формате плейлиста с плеером и списком серий — **без новых
таблиц и без новой сущности**, расширив существующие сюжеты (stories).

## Сравнение концепций

| | tagDiv video playlist | Наши сюжеты (сейчас) |
|---|---|---|
| Суть | Плейлист видео: один главный плеер + список серий | Хронология материалов по теме (любого типа) |
| Тип контента | Только видео | Любой: novost, sobytie, analitika, interesnoe, ideya, video |
| Рендер | Плеер (embed) + сайдбар серий | Вертикальный таймлайн со ссылками на материалы |
| Навигация | Клик по серии меняет плеер без перезагрузки; autoplay next | Переход на отдельную страницу материала |
| Данные | Отдельная сущность/плагин | `stories` + `article_stories` (`is_primary`, `added_via`) |

Вывод: концепции пересекаются частично. Сюжет — уже готовый «плейлист-контейнер»
(состав, главный элемент, публичная страница, админ-конструктор). Не хватает
только **режима отображения** для сюжетов, состоящих из видео.

## Рекомендация

**Видео-режим сюжета**: сюжет, в котором все опубликованные материалы имеют
`type = 'video'`, рендерится на `/syuzhet/:slug` как плейлист (главный плеер +
список серий + автопереход). Никаких новых таблиц, флагов и типов — режим
вычисляется из состава сюжета.

Альтернатива («универсальные плейлисты» из любого контента) отклонена:
плейлист из текста не имеет смысла для пользователя, а усложняет UI.

## Требования

### R1. Обнаружение плейлист-режима

- `StoryPage` (`apps/web/src/pages/StoryPage.tsx`) после загрузки данных
  вычисляет: `isPlaylist = articles.length > 0 && articles.every(a => a.type === 'video')`.
- Правило строгое: **все** элементы — видео. Один текстовый материал возвращает
  сюжет к обычной хронологии (см. «Риски»).
- Пустой сюжет (0 материалов) — обычный режим (пустая хронология).

### R2. Плейлист-режим на StoryPage

При `isPlaylist = true` вместо таймлайна рендерится:

1. **Главный плеер** — `<iframe>` текущей серии через существующий
   `toEmbedUrl()` (`apps/web/src/lib/video.ts`), тот же разметочный паттерн, что
   в `ArticlePage.tsx` (aspect-video, rounded-xl, allow/allowFullScreen).
   Источник видео — `articles[currentIndex].videoUrl`.
2. **Заголовок и описание** текущей серии под плеером (title + excerpt),
   ссылка «Открыть материал →» на `/{type}/{slug}` страницы материала.
3. **Список серий** — сбоку на десктопе (грид 2/3 + 1/3), снизу на мобильном.
   Каждая серия: номер, превью (`videoThumbnail()`), title, дата, бейдж
   «сейчас играет», галочка «просмотрено» (если включён прогресс, см. R4).
4. **Клик по серии** меняет `currentIndex` → плеер пересоздаётся с новым
   `src` **без перезагрузки страницы** (key={article.id} на iframe).

### R3. Автопереход (autoplay next)

- Тумблер «Следующее видео автоматически» (как в YouTube-плейлистах),
  по умолчанию **включён**, состояние в `localStorage`
  (`invrf:playlist-autoplay`).
- Реализация: по событию `ended` — для YouTube через postMessage API
  (YouTube IFrame API, `onStateChange` → `ENDED`); для RuTube/VK — iframe
  не отдаёт события → **принять**: autoplay работает только для YouTube,
  для остальных платформ тумблер скрыт/выключен (заглушка на будущее).
- При включённом autoplay по окончании серии: автоматический переход к
  следующей (без цикла: последняя серия — стоп).

### R4. Прогресс просмотренных серий

- **Отложить.** Отдельная задачей позже (метки «просмотрено» в localStorage,
  либо серверные `article_views`, которые уже есть в схеме).
- В рамках этого ТЗ — не делаем.

### R5. Главная статья (is_primary) = первая серия

- Первая серия плейлиста — материал с `is_primary = true`
  (`article_stories.is_primary`), если он есть; иначе — первый по порядку.
- Плеер при загрузке страницы показывает первую серию.

### R6. Порядок серий

- Сейчас порядок в `GET /stories/:slug` — `ORDER BY articles.published_at ASC`
  (`apps/api/src/routes/stories.ts`). Колонки `sort_order` в `article_stories`
  **нет** (проверено по `packages/db/src/schema.ts`).
- MVP плейлиста: порядок = хронология публикации (`published_at ASC`), как сейчас.
- **Рекомендуемое расширение (в рамках этого же ТЗ, маленькая миграция):**
  добавить в `article_stories` колонку `sort_order integer NOT NULL DEFAULT 0`,
  сортировать сюжет по ней (с fallback на `published_at`). Это нужно, чтобы
  редактор мог задать порядок «выпусков» независимо от дат публикации
  (например, переупорядочить серию после публикации). Миграция: Drizzle +
  SQL `ALTER TABLE article_stories ADD COLUMN sort_order ...;`
- Админка: в `StoryEditPage` порядок выбранных материалов хранится в
  `selected: number[]` — порядок кликов/массива и есть порядок. С `sort_order`
  нужно передавать упорядоченный массив и писать индекс в `sort_order`
  в `PUT /stories/:id/articles`.

### R7. API

- `GET /stories/:slug` (`apps/api/src/routes/stories.ts`): добавить в селект
  поле `videoUrl: articles.videoUrl` — без него плеер на StoryPage не построить.
- Сортировка: `asc(articleStories.sortOrder)` (если R6 принят), fallback
  `asc(articles.publishedAt)`.
- Остальные эндпоинты (`/stories/:id/articles` PUT/GET) — меняются только
  в части записи/чтения `sort_order`.

### R8. Админка

- Ничего нового не строим. Конструктор сюжетов (`apps/admin/src/pages/StoriesPage.tsx`,
  `StoryEditPage.tsx`) уже умеет: состав через чекбоксы, «сделать главной».
- Если принят R6 — в `StoryEditPage` добавить кнопки ↑/↓ для переупорядочивания
  выбранных материалов (или drag-and-drop, но ↑/↓ дешевле и надёжнее).

## Реализация (файлы)

1. **`apps/api/src/routes/stories.ts`** — добавить `videoUrl` в SELECT
   `GET /stories/:slug`; сортировка по `sort_order`.
2. **`packages/db/src/schema.ts`** — `articleStories.sortOrder`
   (`sort_order`, integer, default 0) + миграция SQL.
3. **`apps/api/src/routes/stories.ts`** — `PUT /stories/:id/articles`: писать
   `sort_order` по индексу массива `articleIds`.
4. **`apps/web/src/pages/StoryPage.tsx`** — основной объём работ:
   - вычисление `isPlaylist`;
   - новый компонент плейлиста (можно вынести в
     `apps/web/src/components/StoryPlaylist.tsx`): плеер, список серий,
     текущий индекс, тумблер autoplay (YouTube-only), переходы;
   - обычный таймлайн не трогаем — условный рендер.
5. **`apps/web/src/api.ts`** — тип `StoryDetail`: добавить `videoUrl` в элементы
   `articles`.
6. **`apps/admin/src/pages/StoryEditPage.tsx`** — ↑/↓ для порядка (если R6).

## Критерии приёмки

1. Сюжет, состоящий только из опубликованных `type=video`, открывается на
   `/syuzhet/:slug` в плейлист-режиме: главный плеер + список серий.
2. Первая серия = материал с `is_primary` (или первый по порядку); его видео
   в плеере при загрузке.
3. Клик по серии меняет видео в плеере без перезагрузки страницы.
4. Тумблер autoplay включён по умолчанию; для YouTube-серий по окончании
   автоматически грузится следующая; тумблер сохраняется в localStorage.
5. Смешанный сюжет (видео + текст) и текстовый сюжет рендерятся прежней
   хронологией — без изменений.
6. Обычные (не видео) сюжеты: регрессий нет — верстка, избранное, хронология.
7. Если принят `sort_order`: порядок серий в плейлисте соответствует порядку,
   заданному в админке (↑/↓), а не датам публикации.

## Риски

| Риск | Митигация |
|---|---|
| **Смешанные сюжеты** (видео + текст). Порог «80% видео» хрупок и непредсказуем для редактора. | Простое строгое правило: **все** элементы `type='video'` → плейлист. Иначе — обычная хронология. Правило задокументировать в админке (подсказка в StoryEditPage: «все материалы — видео → страница станет плейлистом»). |
| Autoplay для RuTube/VK невозможен (iframe не шлёт события) | Тумблер показывать только когда текущая серия — YouTube; в ТЗ зафиксировано. |
| YouTube IFrame API добавляет скрипт и слушателей postMessage | Грузить API лениво, только в плейлист-режиме; отписываться на unmount. |
| `published_at ASC` не всегда желаемый порядок выпусков | Миграция `sort_order` (R6) — рекомендуется сразу, чтобы не менять API дважды. |
| Материал `type='video'` без `video_url` или с нераспознанной платформой (`toEmbedUrl` → null) | В плейлисте такая серия показывает превью-заглушку и по клику ведёт на страницу материала; из автоплея исключается. |
| Плейлист-режим ломает ожидание от «Сюжета» у части аудитории | Под заголовком в плейлист-режиме оставить ссылку «Все материалы сюжета» — якорь на полную хронологию ниже (хронологию можно оставить под плейлистом или прятать за аккордеоном — решить при вёрстке; по умолчанию — скрыть, показать по ссылке). |
