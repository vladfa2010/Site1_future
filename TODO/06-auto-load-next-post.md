# 06 — Auto-load next post (бесконечное чтение внизу страницы статьи)

**Статус:** ТЗ (к реализации)
**Дата:** 2026-11-08
**Владелец фичи:** «автолоад некст пост делаем в самом низу страницы. после всех блоков» (фича из донора Newspaper)

---

## 1. Цель

Когда читатель доскролливает страницу статьи до самого низа (после контента и всех каруселей — `IdeaEvents`, `TypeCarousel`), подгружается и рендерится на этой же странице **следующая** статья. Дальше — ещё одна, и так максимум 3 подряд. Цель — рост глубины сессии и числа просмотров (`article_views`), как у донора.

---

## 2. Текущее состояние (референсы в коде)

- `apps/web/src/pages/ArticlePage.tsx` — SPA-страница статьи (`/:type/:slug`, роут в `apps/web/src/App.tsx:29`).
  - Основной контент: `Breadcrumbs` → тип → `h1` (+ Favorite/Subscribe для `ideya`) → тезис → `EntityChips` → `IdeaEvents (sobytie)` → видео (для `type=video`) → `contentHtml` (санитайзер `sanitizeArticleHtml`) → `IdeaChart` → `sourceUrl` → нижний блок каруселей (только для `ideya`): `IdeaEvents (novost)`, `TypeCarousel analitika/interesnoe/ideya`.
  - Карусели объявлены прямо в этом файле: `IdeaEvents` (строки 17–38), `TypeCarousel` (строки 41–65).
- Просмотр фиксируется **на бэкенде** при `GET /api/articles/:type/:slug`: `apps/api/src/routes/articles.ts:158` — `db.insert(articleViews)` (fire-and-forget). То есть «просмотр подгруженной статьи» = успешный фетч её detail-эндпоинта.
- Пейволл: тот же эндпоинт отдаёт `403 { error: 'forbidden', access: 'auth'|'tariff' }` (`articles.ts:125–134`). На фронте это ловится в `ArticlePage` (строки 76–79) и показывается `<Paywall access=… title="Закрытый материал" />` (`apps/web/src/components/Paywall.tsx`).
- Лента для выбора «следующей»: `GET /api/articles?type=…&limit=…` — уже используется фронтом (`api.byType`, `apps/web/src/api.ts:91`), сортировка `coalesce(publishedAt, createdAt) desc` (`articles.ts:104`), отдаёт только то, что доступно юзеру по пейволлу (фильтр `accessCondition`, `articles.ts:68–69`). Поля карточки: `id, type, slug, title, excerpt, publishedAt, coverUrl, videoUrl` (`api.ts:12–21`).
- Дата-фетчинг — React Query (`@tanstack/react-query`), ключи вида `['article', type, slug]`.
- `document.title` сейчас **никуда не выставляется** — управление заголовком нужно добавить.

## 3. Требования

### 3.1. Поведение

1. В самом низу `ArticlePage` (после нижнего блока каруселей, внутри `<article>` или сразу за ним) ставится **sentinel-элемент** (пустой `<div ref>` высотой 1 px).
2. Когда sentinel попадает во вьюпорт — запускается подгрузка следующей статьи. Только **IntersectionObserver**, без сторонних библиотек. `rootMargin: '600px'` — начинаем грузить чуть раньше, чтобы контент появлялся до того, как юзер упрётся в низ.
3. Лимит глубины: **максимум 3 подгруженные статьи подряд**. После третьей вместо sentinel показывается ссылка-кнопка **«Читать дальше»** → ведёт на detail-страницу следующей статьи (по той же логике выбора, обычным переходом SPA). Клик — навигация, не подгрузка.
4. Загрузки не должны запускаться параллельно: пока идёт фетч, sentinel «отключён» (флаг `loading`), повторный триггер не порождает дубли.

### 3.2. Логика выбора «следующей» статьи (рекомендация)

Варианты, которые обсуждались:

- **A. Следующая по `published_at` внутри того же типа** — предсказуемая лента, ровно как у лент по типу (`byType`).
- **B. Общая лента (все типы)** — менее релевантно, размывает контекст.
- **C. Related по трендам/теме** — максимально релевантно, но сложнее: связи (`article_trends`) есть в detail-ответе (`relations.trends`), а лента по тренду есть (`/api/trends/:slug`), но сборка «related-приоритета» — это новая бэкенд-логика и отдельный эндпоинт.

**Решение: A как базовое поведение.** Приоритет выбора:

1. Сначала — **та же выборка, что и карусели «по идее»**: если у текущей статьи есть привязки к трендам (`relations.trends`), берём первый тренд и его ленту `/api/trends/:slug` — это самая «горячая» смежная тематика, та же идея/тема, что и у донора. Статьи исключаем: уже показанные (текущая + все подгруженные).
2. Если трендов нет или лента тренда пуста — **следующая по `published_at` внутри того же типа** (`byType(currentType, limit=20)`), минус уже показанные.
3. Если в типе больше ничего нет — **любая published** (`byType` без фильтра), минус уже показанные.

То есть упрощённо: **сначала та же тематика (тренд → карусель «по идее»), потом тот же тип, потом любая published.** Все кандидаты — только из уже доступных публичных эндпоинтов, новых эндпоинтов не требуется.

> Если позже захотим чистый «related по трендам» без каскада — это отдельная задача с новым эндпоинтом `GET /api/articles/:id/next` на бэкенде. В ТЗ закладываем каскад на фронте, чтобы не трогать API.

### 3.3. Рендер подгруженной статьи (минимальный набор)

Каждая подгруженная статья рендерится **без** каруселей и «служебных» блоков идеи. Минимальный набор:

- разделитель-заголовок **«Следующий материал»** (`<hr>` + подпись, стилистика как у заголовков каруселей: `text-sm font-semibold uppercase tracking-wide text-zinc-500`);
- **заголовок** `h2` со ссылкой `/{type}/{slug}` (кликабелен — нормальная навигация);
- **тип** (`TYPE_LABELS[article.type]`, мелкий uppercase);
- **контент целиком**: тот же `contentHtml` через `sanitizeArticleHtml`, с тем же prose-стилем, что основная статья;
- **источник** (`sourceUrl`) — как в основной статье;
- **чипсы** `EntityChips` по `relations` — да, оставляем: это навигация «проваливание из любой точки» (раздел 4.2 проекта) и дешёвый компонент;
- **крошки** — **нет** (дублируют тип и утяжеляют бесконечную ленту);
- видео (`type=video` с `videoUrl`) — **да**, embed-блок через `toEmbedUrl` (дешево, тот же код);
- тезис/график/избранное-подписка/карусели/события по идее — **нет**.

Итого структура подгруженного блока: `NextMaterialSeparator` → `h2`-ссылка → тип → `EntityChips` → (video?) → contentHtml → источник.

### 3.4. URL и history

Обсуждённые варианты:

- **Не менять URL** — плюс: никаких проблем с навигацией назад; минус: шеринг копирует адрес первой статьи, а юзер прочитал третью; аналитика внешних систем видит «не ту» страницу.
- **`history.replaceState` на последнюю загруженную статью** — URL в адресной строке всегда соответствует тому, что юзер читает внизу; `document.title` = заголовок последней подгруженной. Плюсы: шеринг и «скопировать ссылку» отдают актуальную статью; title вкладки адекватный. Минусы: кнопка «назад» вернёт на предыдущий маршрут (не на предыдущую статью) — приемлемо, потому что `replaceState`, а не `pushState`, записей в истории не добавляется; React Router при этом не уведомляется — согласованность держим за счёт того, что меняем только `window.history`/title, состояние роутера не трогаем.

**Решение: `replaceState` + `document.title` на последнюю загруженную статью.** (Аналитика просмотров не зависит от URL — она фиксируется на бэкенде при фетче detail, см. 3.5.)

Требования к title: формат `«{title}» — инвестиционно.рф`. Возврат title/URL к исходному — при уходе со страницы (unmount) или при выходе из вкладки не требуется: SPA уничтожает страницу, следующий маршрут сам выставит своё. **Важно:** сейчас title вообще никто не выставляет — добавляем установку title и для основной статьи, и для подгруженных (единый механизм).

### 3.5. Фиксация просмотра (article_views)

- Просмотр подгруженной статьи фиксируется **на бэкенде при фетче** `GET /api/articles/:type/:slug` (`articles.ts:158`) — отдельного beacon с фронта **не нужно**.
- **Триггер: при загрузке, а не при появлении в вьюпорте.** Обоснование: фетч стартует по IntersectionObserver с `rootMargin 600px`, т.е. за ~экран до показа; в момент реального появления в вьюпорте контент уже отрендерен. Задержка между фиксацией и показом < 1 экрана скролла — допустимая погрешность, а логика остаётся нулевой (дублирование механизма основной статьи).
- При 403 (пейволл) detail-эндпоинт **не** пишет просмотр (ответ уходит до строки 158) — поведение совпадает с основной страницей, это правильно.

### 3.6. Пейволл

- Если detail-запрос подгруженной статьи вернул `403 {access: 'auth'|'tariff'}` — вместо контента рендерим **встроенный paywall-блок**: `<Paywall access={…} title="Закрытый материал" />` внутри блока подгруженной статьи (после разделителя и заголовка-ссылки — чтобы читатель видел, что именно закрыто).
- Эта статья засчитывается в лимит 3 (иначе — потенциальная бесконечная череда paywall-блоков).
- Блок Paywall имеет собственную ширину/центрирование (`mx-auto max-w-md py-10`) — при встраивании в ленту обернуть в контейнер с горизонтальными отступами; убедиться, что кнопка «Войти» (authModal) корректно открывает модалку из середины страницы.

### 3.7. Производительность и отмена

- Каждая подгруженная статья — **отдельный React Query запрос** со своим ключом (`['article', type, slug]` — тот же, что и у основной: дедупликация бесплатна, если эта статья уже была открыта в сессии).
- **Abort на уходе:** фетч detail должен отменяться при unmount страницы. Сейчас `api.get` не пробрасывает `signal` — расширить `get(path, signal?)` и прокидывать `signal` из `useQuery` (React Query делает это через `queryFn: ({ signal }) => …`).
- Контент каждой подгруженной статьи — это её DOM в общем дереве; страницы из 4 полных статей приемлемы, но:
  - картинки/iframe — с `loading="lazy"` (у video-embed уже стоит);
  - карусели подгруженных статей не рендерим (см. 3.3) — это и есть главный бюджет.
- Скролл не должен «прыгать» при вставке: контент вставляется **после** текущего низа; IntersectionObserver срабатывает один раз на sentinel до загрузки, так что скачок от вставки блока выше sentinel невозможен (вставка всегда ниже).

## 4. Реализация (файлы)

### 4.1. Новый компонент

**`apps/web/src/components/AutoLoadNext.tsx`** — экспортирует `<AutoLoadNext current={article} relations={relations} />`, рендерится в конце `ArticlePage` (после нижнего блока каруселей, строки 160–167).

Состояние внутри:

```ts
type Loaded = {
  type: string;
  slug: string;
  status: 'loading' | 'ok' | 'paywall-auth' | 'paywall-tariff';
};
const [loaded, setLoaded] = useState<Loaded[]>([]);
const [exhausted, setExhausted] = useState(false); // лента кончилась → «Читать дальше» или скрыть
```

Логика:

1. **Кандидаты** — вычисляются лениво при первом триггере: каскад 3.2 (тренд → тот же тип → любая), исключая `current.id` и все уже подгруженные (`id` сохраняем из detail-ответа). Кандидаты — это `{type, slug}` из лентовых эндпоинтов (`api.byType`, `api.trend`).
2. **Sentinel**: `useRef<HTMLDivElement>` + `useEffect` с `new IntersectionObserver(cb, { rootMargin: '600px' })`; в `cb` при `isIntersecting && !loading && loaded.length < 3 && !exhausted` — взять следующего кандидата, добавить в `loaded` со статусом `loading`, запустить запрос.
3. **Запрос detail**: `useQuery` нельзя динамически «добавлять»; используем либо (а) один хук `useQueries` поверх массива `loaded`, либо (б) императивный `api.article()` с ручным `loading`-флагом. **Рекомендация: (а) `useQueries`** — получаем статусы/abort/кэш из коробки.
4. **Результат**: `ok` → блок 3.3; `403` → `err.status === 403 && err.body?.access` → блок с `<Paywall>` (3.6). `404`/сетевая ошибка → пропускаем кандидата, берём следующего (не считаем в лимит? — **считаем**, иначе зациклимся на битых slug).
5. **URL/title**: `useEffect` при каждом новом `ok`-элементе: `window.history.replaceState(null, '', \`/${type}/${slug}\`)`, `document.title = \`«${title}» — инвестиционно.рф\``. Также единый эффект в `ArticlePage`: при загрузке основной статьи выставить title основной (первый подгруженный «перекроет» его).
6. **После 3-й**: sentinel убирается, рендерится `exhausted`-ссылка «Читать дальше» (`Link to={nextRoute}` по той же логике кандидатов, если кандидаты ещё есть) или ничего, если кандидаты кончились.

### 4.2. Правки существующих файлов

- **`apps/web/src/api.ts`**:
  - `get(path, signal?)` — принимать `AbortSignal`, пробрасывать в `fetch`.
  - `api.article(type, slug, signal?)`, `api.byType(type, limit, signal?)`, `api.trend(slug, signal?)` — проброс signal.
  - `api.trend` уже есть; убедиться, что возвращает `articles` с `type` и `slug` (см. `TrendDetail`) — да, `ArticleListItem[]`.
- **`apps/web/src/pages/ArticlePage.tsx`**:
  - внизу (после строки 167) добавить `<AutoLoadNext current={article} relations={relations} />`;
  - добавить `useEffect` для `document.title` основной статьи.
- **`apps/web/src/components/Paywall.tsx`** — без изменений; при необходимости добавить опциональный проп `embedded?: boolean` для компактных отступов при встраивании (по вкусу, не обязательно).

### 4.3. Бэкенд

**Изменений не требуется.** Все данные берутся из существующих эндпоинтов:
- `GET /api/articles?type=…&limit=…` (`articles.ts:61`) — лента типа/всех, сортировка по дате, пейволл-фильтр уже встроен.
- `GET /api/trends/:slug` — лента тренда.
- `GET /api/articles/:type/:slug` (`articles.ts:112`) — detail + фиксация просмотра + пейволл-403.

## 5. Критерии приёмки

1. Открыть любую опубликованную статью, доскроллить до самого низа (после всех каруселей) — **автоматически подгружаетcя следующая** статья по логике 3.2, с разделителем «Следующий материал».
2. Подряд подгружается **максимум 3** статьи; после третьей — ссылка «Читать дальше» (или тишина, если лента кончилась). Четвёртая автоматически не подгружается ни при каком скролле.
3. После подгрузки **URL (`replaceState`) и `document.title`** соответствуют последней загруженной статье; при клике на заголовок подгруженной статьи — нормальный переход SPA на её страницу.
4. Для каждой успешно подгруженной статьи в `article_views` появляется запись (проверить SQL/`/admin/metrics`), для paywall-заблокированной — нет.
5. Подгруженная статья с `accessLevel = 'auth'/'tariff'` показывает **paywall-блок** вместо контента; кнопка входа/тарифа открывает модалку / ведёт в кабинет.
6. Уход со страницы во время подгрузки — запрос **отменён** (abort), без ошибок в консоли; возврат «назад» ведёт на корректную страницу (история не засорена pushState).
7. Никаких дублей: та же статья не подгружается дважды (проверить при возврате на страницу из кэша React Query).
8. `npm run build` (или `tsc`) в `apps/web` — без ошибок; ручной прогон: статья `ideya` с трендами, статья без трендов, статья последняя в своём типе, закрытая тарифом статья в ленте кандидатов.

## 6. Риски и ограничения

| Риск | Описание | Митигация |
|---|---|---|
| **SEO vs скрытый контент** | Контент 3 подгруженных статей появляется в DOM одной страницы; поисковики могут счесть это каннибализацией/клоакингом, а `replaceState` меняет URL без реального документа по этому адресу. | Рекомендация: подгруженные блоки пометить `data-autoload` и исключить через `rendered DOM ≠ crawlable snapshot`: в `index.html`/SSR-мета оставлять только основную статью; убедиться, что canonical/OG каждой статьи доступен по её собственному URL (`/:type/:slug` при прямом заходе сервер отдаёт корректные meta — проверить текущий серверный рендер мета). Минимально: не индексировать якоря автозагрузки, на внутренних ссылках на подгруженные статьи всегда стоять нормальные `<Link>`. |
| **Дублирование просмотров** | Юзер доскроллил до статьи B (просмотр засчитан на фетче), вернулся по «назад» и открыл B заново — просмотров два. Так же устроена и основная страница — поведение осознанное (просмотр = факт доставки контента), не баг. | Если аналитике понадобится «уникальные просмотры» — дедупликация на уровне отчётов (`count(distinct user_id, article_id)`), не на записи. В ТЗ не входит. |
| **Несогласованность URL и роутера** | `replaceState` обходит React Router: после подгрузки F5 обновит страницу и откроет **подгруженную** статью как основную — это и есть желаемое поведение («шеринг актуальной»), но юзер потеряет контекст предыдущих. | Принято как фича донора. Обратный скролл к предыдущим статьям — по скроллу, не по истории. |
| **Производительность длинной страницы** | До 4 полных статей + карусели основной. | Без каруселей в подгруженных, `loading="lazy"` на медиа, abort сигналы. При просадках — виртуализация отложена (явно не входит). |
| **Зацикливание на битых кандидатах** | 404/сеть при фетче detail. | Ошибочный кандидат идёт в счёт лимита 3 и берётся следующий (4.1 п.4). |
| **Paywall-чередa** | В ленте кандидатов много закрытых материалов → несколько paywall-блоков подряд. | Лента `/api/articles` уже отфильтрована по доступу (`accessCondition`) — кандидаты по умолчанию доступны; paywall всплывёт только при гонке прав/истёкшем тарифе. Приемлемо. |
