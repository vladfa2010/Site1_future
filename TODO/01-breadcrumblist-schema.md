# ТЗ-01: JSON-LD BreadcrumbList (schema.org) на всех публичных страницах

- **Статус:** черновик
- **Дата:** 2026-11-08
- **Связи:** блокируется частично SPA-ограничением; финальный фикс — ТЗ-10 (SSR). URL 1:1 с донором — SEO-критично, не ломать.

---

## 1. Цель

Донор (WordPress, тема Newspaper) отдаёт в `<head>` разметку `BreadcrumbList` (JSON-LD, schema.org), по ней Google строит хлебные крошки в сниппете. При переезде на SPA (React 19, Vite) эта разметка пропала — рискуют позиции: сниппеты теряют строку крошек (CTR ↓), глубина обхода и понимание структуры сайта ботами ухудшаются. Задача: вернуть `BreadcrumbList` на каждой публичной странице в DOM с теми же URL, что у донора (1:1).

Результат для выдачи: сниппет вида `инвестиционно.рф › Новость › <заголовок>` и корректная передача иерархии «раздел → материал» поисковику.

## 2. Текущее состояние

Прочитано в репозитории (пути от корня `apps/web`):

- **Визуальные крошки есть, семантической разметки нет.** `src/components/Breadcrumbs.tsx:9-26` рендерит `<nav aria-label="Хлебные крошки">` со ссылками, но это обычный HTML-список ссылок — микроразметки `BreadcrumbList` нет ни в одном компоненте (поиск по `src` ничего не нашёл).

Хуков `document.title` / мета-менеджмента в `src` нет — `<title>` и `<meta description>` захардкожены в `apps/web/index.html:6-7` для всех страниц сайта.
- **Заведомо неверная посылка исходного ТЗ:** «react-helmet-async уже подключён» — не соответствует коду. Добавление его — часть этого ТЗ (must), либо разметку вставляем голым `<script>` из `useEffect` (не рекомендуется — хуки рендера правильнее).

## 3. Требования

### Must

1. На каждой публичной странице из §4 в `<head>` (или в начале `<body>` — Google принимает оба, предпочтительно `<head>`) должен присутствовать ровно один блок `<script type="application/ld+json">` с объектом `{"@context":"https://schema.org","@type":"BreadcrumbList","itemListElement":[...]}`.
2. Каждый элемент `itemListElement`: `position` (1-based), `name`, `item` — **абсолютный URL** (`https://инвестиционно.рф/…`, punycode-эквивалент `https://xn--80aqfgda1a8a.xn--p1ai/…` — использовать канонический хост из конфигурации деплоя, не хардкодить в каждом компоненте). Последний элемент текущей страницы — без `item` или с `item` = canonical текущего URL (по спецификации Google последний элемент может быть без `item`; единообразно решить и зафиксировать здесь: **все элементы, включая последний, с `item`** — упрощает генератор).
3. Имена элементов (`name`) совпадают с лейблами визуальных крошек из §2 (один источник данных — см. §6).
4. Абсолютные URL в разметке совпадают 1:1 с URL донора для соответствующих материалов (слаг не транслитерировать, не менять).
5. Установить `react-helmet-async`, обернуть приложение в `HelmetProvider` (точка входа `src/main.tsx`), JSON-LD вставлять через `<Helmet><script type="application/ld+json">{...}</script></Helmet>`.
6. В JSON экранировать `</script>` в текстах (`<` → `\u003c`), чтобы заголовок материала не ломал вёрстку при вставке в script-блок.

### Should

7. Единый компонент-хелпер `JsonLdBreadcrumbs({ items }: { items: { name: string; url: string }[] })`, строящий объект разметки, чтобы страницы не собирали JSON руками.
8. Совместить источник цепочки: расширить `Crumb` в `Breadcrumbs.tsx:3-6` опциональным `url?: string` и генерировать визуальные крошки и JSON-LD из одного массива на странице.
9. Подтянуть заодно `document.title` через тот же `Helmet` (title/description сейчас глобальные из `index.html:6-7`) — если по объёму разрастается, вынести в отдельное ТЗ, но Helmet всё равно нужен для must-5.
10. Для SPA-ограничения: зарегистрировать задачу ТЗ-10 (SSR / пререндер), этот ТЗ закрывает только клиентскую часть.

### Не делаем (out of scope)

- SSR, пререндер, prerender-спайдерботам ответы — ТЗ-10.
- Разметка `Article`, `Organization`, `WebSite` (sitelinks searchbox) — отдельные ТЗ.
- Крошки в выдаче для страниц с query-фильтрами (`/portfolio?…`) — Google по BreadcrumbList не отражает query-параметры в крошках; обрабатываем по схеме §4.6.

## 4. Схемы данных по типам страниц

Роуты — из `src/App.tsx`. Канонический хост обозначен `<SITE>`.

### 4.1 Главная `/` (HomePage)

Разметку не выводим (крошек нет, одноуровневая страница). Если требование «ровно один блок» нарушается — оставить пустым; решение: **не выводить скрипт на главной**.

### 4.2 Статья `/:type/:slug` — ArticlePage (App.tsx:29)

`type ∈ {novost, ideya, analitika, interesnoe, sobytie, video}` (KNOWN_TYPES, `TypePage.tsx:5`).

```
1. Главная        <SITE>/
2. <TYPE_LABELS[type]>   <SITE>/<type>
3. <заголовок материала> <SITE>/<type>/<slug>
```

Данные: `article.type`, `article.title`, `article.slug` из `api.article(type, slug)` (ArticlePage.tsx:69-72). Имя третьего элемента — полный заголовок (в визуальных крошках он обрезается до 60 символов, `ArticlePage.tsx:93` — для JSON-LD обрезку не применять, это отдельный источник данных).

### 4.3 Архив типа `/:type` — TypePage (App.tsx:56)

```
1. Главная        <SITE>/
2. <TYPE_LABELS[type]>   <SITE>/<type>
```

Роут `/:type` лежит ПОСЛЕ всех явных путей (App.tsx:56), известные типы валидируются через KNOWN_TYPES.

### 4.4 Тренд `/trend/:slug` — TrendPage (App.tsx:32)

```
1. Главная   <SITE>/
2. Тренды    <SITE>/trend   ← НОВЫЙ элемент-раздел
3. <имя тренда>  <SITE>/trend/<slug>
```

⚠️ Несоответствие с донором/логикой: визуальные крошки (TrendPage.tsx:49) выводят `Тренды` без ссылки. URL `<SITE>/trend` в роутинге не существует — `/:type` его не поймает, упадёт в 404. **Решение (must):** либо у элемента 2 опустить `item` (имя без URL допустимо у непоследнего элемента по спецификации schema.org, Google это допускает), либо создать индексную страницу `/trend`. Рекомендация ТЗ: **опустить `item` у элемента 2** (без изменения роутинга), индексные страницы трендов/сюжетов — отдельная задача. Аналогично для сюжета и компании:

### 4.5 Компания `/kompaniya/:slug` — CompanyPage (App.tsx:31)

```
1. Главная             <SITE>/
2. Скринер проектов    <SITE>/portfolio
3. <имя компании>      <SITE>/kompaniya/<slug>
```

Элемент 2 — реальный URL (`/portfolio`, App.tsx:34).

### 4.6 Сюжет `/syuzhet/:slug` — StoryPage (App.tsx:33)

```
1. Главная   <SITE>/
2. Сюжеты    (без item — индексной страницы нет)
3. <имя сюжета>  <SITE>/syuzhet/<slug>
```

### 4.7 Скринер `/portfolio` — PipelinePage (App.tsx:34)

```
1. Главная             <SITE>/
2. Скринер проектов    <SITE>/portfolio
```

Query-параметры (`phase`, `stage`, `industry`, `trend`) в JSON-LD **не отражаем**: элементы крошек с query-параметрами Google игнорирует/пессимизирует; текущая страница всегда `/portfolio`. Визуальные крошки (PipelinePage.tsx:85) могут показывать фазу/тренд — JSON-LD упрощённый, несоответствие допустимо и фиксируется здесь как осознанное.

### 4.8 Поиск `/search` — SearchPage (App.tsx:42)

```
1. Главная   <SITE>/
2. Поиск     <SITE>/search
```

(Кандидат в should; визуальных крошек сейчас нет — разметка опережает UI, допустимо.)

### 4.9 Лента `/feed`, личный кабинет и служебные страницы

`/feed`, `/cabinet`, `/login`, `/register`, `/propose`, `/pricing`, `/privacy`, `/terms`, статики донора (StaticPage, AboutPage) — **разметку не выводим**: служебные/персональные страницы не должны получать крошки в выдаче. Исключение: `/pricing`, `/privacy`, `/terms` — опционально (should) цепочка `Главная → <title>`.

### 4.10 404

Роут `*` (App.tsx:57) — разметки нет.

## 5. SPA-ограничение (известное, фиксируем)

Боты без JS (старые краулеры, некоторые агрегаторы) получат из `curl`/HTTP-ответа только `index.html` без разметки — JSON-LD в DOM появляется только после выполнения бандла. Googlebot рендерит JS (WRS), поэтому основной поисковик покроется; Яндекс умеет JS-рендеринг частично и с задержкой. **Это принятое ограничение ТЗ-01; полное решение — ТЗ-10 (SSR/пререндер)**, после которого разметку переносим в ответ сервера 1:1 (генератор цепочки из §6 должен быть переиспользуемым: не привязывать к `window.location`).

Отдельно: экран пейволла (403 на статье) — рендерится без крошек. Решение: на Paywall-экране тоже выводить BreadcrumbList по известному `type/slug` (заголовок недоступен — использовать slug-подобную подстановку недопустимо; допустимо не выводить разметку на 403-экране). Рекомендация: **не выводить на 403**.

   - `src/pages/SearchPage.tsx` (опционально);

6. (Should-8) `src/components/Breadcrumbs.tsx:3-6` — добавить `url?: string` в `Crumb` и опционально генерировать оба представления из одного массива.
7. Проверить, что Helmet-скрипты не дублируются при переходах между страницами по клиентскому роутингу (Helmet должен заменять, а не дополнять — протестировать на переходе Статья A → Статья B).

## 7. Критерии приёмки

1. **Валидация структуры.** URL-ы всех типов из §4 (по одному примеру каждого + главная и 404 как контроль отсутствия) прогнаны через Google Rich Results Test — тип «Breadcrumbs» распознаётся, ошибок нет, URL-ы элементов совпадают с адресной строкой 1:1.
2. **E2E в отрендеренном DOM.** Playwright-сценарий (dev-сервер `npm run dev` в `apps/web`):
   - открыть `/novost/<существующий slug>` → в DOM ровно один `script[type="application/ld+json"]`, внутри валидный JSON с тремя элементами, `item[2].item` оканчивается на текущий URL;
   - клиентский переход на другую статью → предыдущий скрипт заменён, не продублирован;
   - `/trend/<slug>` → элемент 2 без `item` (или с корректным, если принято решение о `/trend`-индексе);
   - `/portfolio?phase=portfel` → разметка содержит 2 элемента, query-параметров нет;
   - главная `/` → блока нет.
   `curl` для проверки НЕ подходит (не исполняет JS) — только браузерный раннер; отметить в отчёте о приёмке.
3. **Совпадение с донором.** Для 10 случайных материалов URL крошек в новой разметке идентичны URL в разметке донора (сверка с кэшем/выдачей, не по живому донору, если он уже отключён — источник истины: миграционный дамп слаг-URL).
4. Тест на экранирование: материал с `<`, `&`, кавычками в заголовке не ломает вёрстку, JSON валиден (`JSON.parse` в консоли браузера).
5. `npm run typecheck` в `apps/web` — без ошибок; линт бандла без регрессий размера (>3 кB gz — предупреждение).
