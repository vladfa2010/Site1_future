## Фича 1: ИИ-генерация заголовка

### Текущее состояние
Кнопки «✨ Сгенерировать из текста» (лид), «✨ Сгенерировать (SEO)» (meta description), «✨ Сгенерировать обложку». Все — фронт-надстройки над `POST /api/media/generate-text` (единый эндпоинт, промпт собирается на клиенте, серверный persona 'editor'). **Серверные изменения не требуются.**

### Требования
1. Кнопка **«✨ Заголовок»** — в строке поля «Заголовок» (справа от инпута, компактный размер `btn-xs`), состояния: idle / «Генерируем…» (disabled).
2. Промпт (паттерн `genExcerpt`, строка ~209 файла): читает ВСЕ поля формы:
   - `ТЕКСТ: ${stripHtml(form.contentHtml).slice(0, 6000)}` (обязательно; если текст < 50 симв → ошибка «Сначала заполните текст статьи», как у лида)
   - `ТЕЗИС:` (если есть), `ТЕКУЩИЙ ЛИД:` (если есть), `УПОМИНАЮТСЯ:` (компании/тикеры/тренды из rels, как в genExcerpt)
   - `ТЕКУЩИЙ ЗАГОЛОВОК (можно улучшить, не копировать): ${form.title}` (если не пуст)
   - `ТИП МАТЕРИАЛА:` — тот же маппинг типов, что в genExcerpt
   - `ТРЕБОВАНИЯ: предложи 3 варианта заголовка через двойной перенос строки, каждый до 100 символов; конкретика (цифры, имена, тикеры) вместо общих слов; без кликбейта и вопросительных заголовков-интриг; на русском.`
3. `maxChars: 400` (3 варианта × ~100 + запас).
4. **Выбор варианта**: после ответа — под полем заголовка блок с 3 кнопками-вариантами; клик → значение в `form.title` (срабатывает существующая цепочка autoSlug), блок вариантов закрывается, notice «Заголовок применён ✓». Повторный клик «✨ Заголовок» — новая тройка вариантов.
5. **Mock-режим** (нет ключа LLM): сервер вернёт `mock: true` — показать один вариант, собранный из первого предложения текста (до 100 симв.), с пометкой «(mock — без ключа)» рядом с кнопкой применения.
6. Ошибки — через существующий `setError` (паттерн genExcerpt).

### Критерии приёмки
- [ ] Кнопка есть в строке заголовка; disabled до тех пор, пока текст статьи ≥ 50 симв.
- [ ] Промпт содержит текст, тезис, лид, сущности, текущий заголовок, тип, требования.
- [ ] 3 варианта рендерятся отдельными кликабельными блоками; клик ставит заголовок и пересчитывает slug (существующая логика autoSlug не сломана).
- [ ] Повторная генерация заменяет блок вариантов.
- [ ] Mock-флаг отображается.
- [ ] Сервер не менялся (дифф только ArticleEditPage).

## Фича 2: Автосохранение черновика раз в минуту

### Проблема
Сохранение только ручное («Сохранить»). Сбой браузера/сети/энергии → потеря всего не сохранённого. Пользователь реально потерял черновик.

### Требования

**Таймер:**
1. Интервал **60 000 мс**, `setInterval` в `useEffect` при монтировании редактора, очистка при размонтировании.
2. Тик выполняет автосохранение **только если**:
   - `dirty === true` (форм изменён с момента последнего успешного сохранения; флаг ставится в `set`/onChange-обработчиках, снимается после любого успешного save);
   - есть что сохранять: `form.title.trim()` или `stripHtml(form.contentHtml).trim()` непусты (пустые черновики не плодим);
   - `busy === false` (нет идущего сохранения — ручного или автоматического);
   - нет открытой модалки подтверждения / ошибки, блокирующей сохранение (в редакторе таких нет — фиксируем для полноты).
3. Ручное сохранение сбрасывает/переинициализирует таймер (не обязательно: тик всё равно проверяет dirty; но после ручного save dirty=false → тик пропускается).

**Статус при автосохранении (важно — не ломаем публикацию):**
4. Новая статья (isNew): автосохранение = `POST /articles` со `status: 'draft'` (НЕзависимо от выбора в форме — автосохранение никогда не публикует). После создания: `setArticleId`, URL заменяется на `/articles/:type/:slug/edit` через `window.history.replaceState` (паттерн — после создания в save()), slug — из autoSlug (существующая логика; если пуст — `draft-${Date.now()}`-нормализованный).
5. Существующая статья, `status === 'draft'`: обычный `PATCH /articles/:id`.
6. Существующая статья, `status === 'published'`: `PATCH` контента, но **статус в payload не включать** (PATCH частичный — сервер не тронет published). Автосохранение опубликованной статьи = тихое обновление текста без смены статуса.
7. `viewsBaseOffset`/`viewsAutoBump` — НЕ слать при автосохранении (это admin-only блок, не трогаем без явного действия).

**Конкурентность и ошибки:**
8. Сериализация: автосохранение не стартует, пока идёт другое сохранение (п.2 busy). Если ручной save нажат во время автосохранения — ручной ждёт завершения (busy), затем выполняется (существующая очередь через disabled кнопки).
9. Ошибка автосохранения: НЕ показывать модально; notice-полоса красным «Автосохранение не удалось (сеть?) — попробуем через минуту», `dirty` остаётся true → повтор на следующем тике. Ручное «Сохранить» доступно всегда.
10. Ответ 409 (slug конфликт при первом автосохранении): сгенерировать slug с суффиксом `-2` и повторить один раз; если снова 409 — ошибка по п.9.

**Индикация:**
11. Рядом с кнопкой «Сохранить»: строка состояния автосохранения:
    - `Автосохранение: вкл` (серый, по умолчанию)
    - спиннер + `Сохраняем…` (во время автосохранения)
    - `Черновик сохранён в 12:03` (зелёный, после успеха; время HH:MM локальное)
    - красный текст ошибки (п.9)
12. После автосоздания (п.4): notice «Черновик создан автосохранением — продолжайте писать ✓».

**Защита от потери при закрытии вкладки (бонус, дешёвый):**
13. `beforeunload`-хендлер: если `dirty` — стандартный браузерный confirm ухода (`e.preventDefault(); e.returnValue = ''`). Только при dirty; снимается после сохранения.

### Что НЕ входит
- Версионирование/история черновиков (отдельное ТЗ, если понадобится).
- Автосохранение в ContentMaster (там одно-действие «Создать черновик»).
- Совместное редактирование.

### Критерии приёмки
- [ ] Правка текста → ровно через ≤60с черновик на сервере (проверяем: после правки, пауза 65с, GET /api/articles/:type/:slug — изменения на месте; URL при этом уже /:type/:slug/edit для новой статьи).
- [ ] Новая статья автосохраняется ТОЛЬКО как draft, даже если в форме «опубликовано».
- [ ] Опубликованная статья после автосохранения остаётся published (GET detail: status published + обновлённый текст).
- [ ] Нет гонок: во время идущего save (ручного) автосохранение не стартует (лог/счётчик запросов).
- [ ] Сбой сети при автосохранении → красная notice, dirty сохранён, повтор через минуту.
- [ ] dirty + закрытие вкладки → браузерный confirm.
- [ ] Пустая форма (нет ни заголовка, ни текста) не создаёт статью автосохранением.
- [ ] viewsBaseOffset/viewsAutoBump не изменяются автосохранением (у статьи с настройками — значения прежние).

### E2E (scripts/e2e.sh)
Автосохранение и генерация заголовка — фронт-логика (curl не исполняет таймеры). Покрываем доступное:
- PATCH существующей published-статьи БЕЗ поля status → статус не меняется (регресс-инвариант п.6): curl-patch текста, затем GET → published.
- generate-text принимает maxChars=400 (валидация диапазона 50–2000): 400 → 200, 2100 → 400.
- Ручной проход (фиксируется здесь): правка → 65с → обновление на сервере; индикатор «Черновик сохранён в HH:MM»; confirm при закрытии dirty-вкладки.

### Реализация
Один файл: `apps/admin/src/pages/ArticleEditPage.tsx` (+ возможно мелкий хук `useAutosave` рядом, если компонент раздуется). Сервер, API, схема БД — без изменений.
